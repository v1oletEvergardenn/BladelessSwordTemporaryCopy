# Dialogue System Player Sequence Commands Cheat Sheet

This project supports custom player commands for Dialogue System sequences.

---

## Quick Start

### Recommended cutscene pattern
1. Use `PClearInput()` before scripted player actions.
2. Chain commands with `->Message(...)` and `@Message(...)` for deterministic order.
3. Mark important cleanup/restore commands as `required` when needed.

---

## Command Reference

## 1) `PAttack(...)`
Forces normal player attack.

### Signature
`PAttack([left|right])`

### Parameters
- `left|right` (optional):
  - attack direction.
  - default: `right`.

### Notes
- Forced mode: ignores normal gameplay gating/cooldown/energy checks.

### Examples
- `PAttack()`
- `PAttack(left)`
- `PAttack(right)`

---

## 2) `PAttackHS(...)`
Forces Heart Sword **CounterAttack only**.

### Signature
`PAttackHS([left|right])`

### Parameters
- `left|right` (optional):
  - attack direction for HS CounterAttack.
  - default: `right`.

### Notes
- This command is hard-bound to `HS_CounterAttack`.

### Examples
- `PAttackHS()`
- `PAttackHS(left)`
- `PAttackHS(right)`

---

## 3) `PHS(...)`
Forces a specific Heart Sword ability by `HSEnum`.

### Signature
`PHS(left|right, hsEnum)`

### Parameters
- `left|right` (required):
  - attack direction context passed to the ability.
- `hsEnum` (required):
  - enum token for ability:
    - `HSCounterAttack`
    - `CriticalSlash`
    - `SlashWave`

### Notes
- Legacy aliases are still accepted for compatibility (for example `counter`, `critical`, `wave`), but `HSEnum` tokens are recommended.

### Examples
- `PHS(left,HSCounterAttack)`
- `PHS(right,CriticalSlash)`
- `PHS(left,SlashWave)`

---

## 4) `PTeleportTo(...)`
Forces designated sword teleport to world point or target.

### Signature
- `PTeleportTo(x,y)`
- `PTeleportTo(targetName)`

### Parameters
- `x,y`:
  - world-space teleport destination.
- `targetName`:
  - scene object name (or subject name) to use as destination.

### Notes
- No `wait|nowait` parameter.

### Examples
- `PTeleportTo(12.5,3.0)`
- `PTeleportTo(BossAnchor)`

---

## 5) `PMoveTo(...)`
Forced move helper with run/walk/custom speed and optional facing.

### Signature
`PMoveTo(xOrTarget[,keep|left|right][,run|walk|speed][,relative|set])`

### Parameters
- `xOrTarget` (required):
  - number: X movement amount or absolute X (based on space mode).
  - string: target GameObject/subject name (moves to target world X).
- `run|walk|speed` (optional):
  - `run`: use run speed.
  - `walk`: use walk speed.
  - `speed`: custom walking speed (example: `1.8`).
  - default: `run`.
- `keep|left|right` (optional):
  - final facing after movement.
  - default: `keep`.
- `relative|set` (optional):
  - numeric `x` only:
    - `relative`: move by delta X from current position.
    - `set`: move to absolute world X.
  - target name:
    - moves to target world X directly.
  - default: `relative`.

### Behavior
- Always waits until movement is complete.

### Examples
- `PMoveTo(5)`
- `PMoveTo(5,walk)`
- `PMoveTo(14,right,run,set)`
- `PMoveTo(2.5,left,1.8,relative)`
- `PMoveTo(BossMark)`
- `PMoveTo("gameobjectName")`
- `PMoveTo(BossMark,walk,left)`

---

## 6) `PFace(...)`
Forces facing direction.

### Signature
`PFace(left|right)`

### Parameters
- `left|right` (required):
  - explicit facing direction.

### Examples
- `PFace(left)`
- `PFace(right)`

---

## 7) `PStop()`
Stops player movement/run-to-target flow.

### Signature
`PStop()`

### Examples
- `PStop()`

---

## 8) `PJump()`
Forces jump.

### Signature
`PJump()`

### Examples
- `PJump()`

---

## 9) `PDoubleJump(...)`
Forces double jump with hold strength.

### Signature
`PDoubleJump([hold=0.2])`

### Parameters
- `hold` (optional):
  - virtual hold time fed into double-jump force scaling.
  - default: `0.2`.

### Examples
- `PDoubleJump()`
- `PDoubleJump(0.35)`

---

## 10) `PGravity(...)`
Toggles player gravity.

### Signature
`PGravity(on|off)`

### Examples
- `PGravity(off)`
- `PGravity(on)`

---

## 11) `PClearInput()`
Clears input states and pending action prep states.

### Signature
`PClearInput()`

### Examples
- `PClearInput()`

---

## 12) `PMoveState(...)`
Switches movement state machine state.

### Signature
`PMoveState(normal|windwalking|standingontemple)`

### Examples
- `PMoveState(normal)`
- `PMoveState(windwalking)`
- `PMoveState(standingontemple)`

---

## 13) `PAnim(...)`
Plays body animator state directly.

### Signature
`PAnim(stateName)`

### Examples
- `PAnim(idle)`
- `PAnim(attack_idle_1)`
- `PAnim(tele_pre_idle)`

---

## 14) `PLegAnim(...)`
Plays leg animator state directly.

### Signature
`PLegAnim(stateName)`

### Examples
- `PLegAnim(leg_idle)`
- `PLegAnim(leg_run)`

---

## Forced Mode Behavior

All player commands are cinematic-authoritative:
- Ignore normal action checks (`CanAttack`, `CanTeleport`, etc.).
- Ignore lock/cooldown/resource gating for command execution.
- Intended for cutscene reliability, not normal gameplay flow.

---

## Sequence Timing Tips

Use message chaining for deterministic behavior:
- `CmdA()->Message(Step1);`
- `CmdB()@Message(Step1)->Message(Step2);`

Use `required` for must-run cleanup:
- `required PStop()@Message(StepX);`

---

## Full Test Sequence (Player Commands)

PClearInput();

PFace(right);
PAnim(idle);
PLegAnim(leg_idle);

PMoveTo(6,run,right,relative)->Message(P1);
PMoveTo(2,walk,left,relative)@Message(P1)->Message(P2);
PMoveTo(14,1.8,keep,set)@Message(P2)->Message(P3);

PAttack(right)@Message(P3)->Message(P4);
PAttackHS(left)@Message(P4)->Message(P5);

PHS(right,HSCounterAttack)@Message(P5)->Message(P6);
PHS(left,CriticalSlash)@Message(P6)->Message(P7);
PHS(right,SlashWave)@Message(P7)->Message(P8);

PTeleportTo(Boss)@Message(P8)->Message(P9);

PJump()@Message(P9)->Message(P10);
PDoubleJump(0.25)@Message(P10)->Message(P11);

PGravity(off)@Message(P11)->Message(P12);
PAnim(idle)@Message(P12)->Message(P13);
PGravity(on)@Message(P13)->Message(P14);

PMoveState(windwalking)@Message(P14)->Message(P15);
PMoveState(normal)@Message(P15)->Message(P16);

required PStop()@Message(P16);
